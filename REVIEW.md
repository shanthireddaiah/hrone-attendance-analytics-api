# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72–74) | Returns `{"status": "ok"}` unconditionally without checking MongoDB connectivity. | `GET /health` returns HTTP 200 even when the database is stopped, unreachable, or credentials are invalid. | Added `client.admin.command("ping")` inside a `try...except` block, returning 200 only if ping succeeds, otherwise raising `HTTPException(status_code=503, detail="Database unavailable")`. |
| 2 | Startup Lifecycle (lines 22–28) | No indexes are created on startup for either `employees` or `attendance_logs`. | At ~100k records, queries perform unindexed collection scans (`COLLSCAN`), causing severe latency and failing the explain requirement. Furthermore, concurrent duplicate creates succeed instead of failing with 409. | Implemented a FastAPI `lifespan` context manager creating unique and compound indexes idempotently (`employees.emp_code`, `attendance_logs(emp_code, date)`, `attendance_logs(date, emp_code)`, etc.). |
| 3 | `compute_late_minutes` (lines 33–37) | Evaluates `minutes > 10` after integer floor division; ignores whole-second truncation (R1). | Shift start `09:30`: punch-in at `09:40:01` (10 min 1 s elapsed) yields `minutes = 10`. Because `10 > 10` is false, it returns `0` instead of `10`. | Truncated punch-in to whole seconds (R1); checked elapsed seconds strictly `> 600`, then computed `int(elapsed_seconds // 60)` per R2. |
| 4 | `compute_late_minutes` & `compute_overtime` (lines 33–47) | Naive timezone handling and missing overnight shift (`shift_end <= shift_start`, e.g. 22:00–06:00) date calculation. | Overnight shift punch-out at 06:40 the next day computes negative overtime because shift end is calculated on the punch-in date instead of `date + 1 day`. | Enforced IST (`UTC+05:30`) timezone conversions; mapped punches before `shift_end` to the previous calendar day's shift date, and advanced the shift end instant by 1 calendar day for overnight shifts (R1). |
| 5 | `compute_work_hours` (lines 40–41) | Uses Python's standard `round()`, which applies Banker's Rounding (round-half-to-even) instead of round-half-up. | Elapsed duration of `2.525` hours rounds to `2.52` instead of `2.53`. | Replaced with exact round-half-up using `Decimal(str(val)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)` (R4). |
| 6 | `compute_overtime` (lines 44–47) | Missing the 30-minute qualification threshold. | Punch-out 25 minutes after shift end returns `25` overtime minutes instead of `0`. | Added threshold check: returns whole floor minutes only if elapsed minutes `>= 30`, otherwise `0` (R3). |
| 7 | `create_employee` (lines 78–85) | Check-then-insert race condition (`find_one` then `insert_one`); missing validation for `shift_start != shift_end`. | Concurrent duplicate `POST /employees` requests with identical `emp_code` both pass the check and attempt insertion; creating an employee with `shift_start == shift_end` succeeds. | Enforced database unique index on `emp_code`, catching `DuplicateKeyError` and raising 409; added validation rejecting `shift_start == shift_end` with 422. |
| 8 | `create_employee` (lines 82–85) | Generates `created_at` as a local naive datetime and serializes it as an ISO string/datetime object instead of integer epoch milliseconds. | Contract violation: `created_at` in the OpenAPI schema requires an integer count of epoch milliseconds. | Stored UTC BSON datetime in MongoDB and converted it to an integer count of epoch milliseconds in API responses. |
| 9 | `list_employees` (lines 88–96) | Off-by-one pagination skip logic (`skip = page * page_size`), total counts entire collection ignoring department filter, and missing sort. | Page 1 skips the first 20 records (showing page 2); filtering by `department` returns a `total` reflecting the whole collection; items are unsorted. | Set `skip = (page - 1) * page_size`; passed the filter query to `count_documents(q)`; added `.sort("emp_code", 1)` (R10). |
| 10 | `punch_in` (lines 99–121) | Missing employee check (crashes with 500); check-then-insert race condition; injects schema-breaking `id`; naive timestamp parsing. | Punch-in for an unknown employee crashes with `TypeError: 'NoneType' object is not subscriptable` (500); concurrent punch-ins duplicate records; response violates schema by injecting `doc["id"]`. | Verified employee exists (404); relied on unique index on `(emp_code, date)` catching `DuplicateKeyError` (409); stripped `_id` and omitted `id`; converted epoch milliseconds to UTC BSON datetime. |
| 11 | `list_attendance` (lines 124–150) | In-memory collection load and sorting (`list(db.attendance_logs.find(q))`); missing inverted date range validation (`date_from > date_to`). | Memory exhaustion and high latency on ~100k records; inverted date ranges (`date_from > date_to`) succeed instead of returning 422. | Pushed sorting (`[("date", -1), ("emp_code", 1)]`), skip, limit, and count directly into the MongoDB cursor; validated `date_from <= date_to` and raised 422 on violation. |

Also note anything you looked at and decided was **not** a defect, and why.

- **Storing calendar dates (`date`, `joined_on`) and shift times (`shift_start`, `shift_end`) as strings**: Examined whether to convert these to BSON datetimes, but confirmed per `DATA_MODEL.md` that plain string storage (`YYYY-MM-DD` and `HH:MM`) is deliberate to avoid timezone pollution.
- **Omission of `_id` in API responses**: Examined whether entities should expose a document ID, but confirmed that `_id` is strictly internal to MongoDB and entities are identified by business natural keys (`emp_code` and `(emp_code, date)`).
- **Reading stored derived fields for analytics**: Confirmed that analytics endpoints must read stored values (`work_hours`, `late_minutes`, `overtime_minutes`, `half_day`) rather than recomputing them dynamically from punch times, per `DATA_MODEL.md` section 3.
